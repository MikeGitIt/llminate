EXECUTIVE SUMMARY
================================================================================
The EnterPlanMode tool cannot execute because the streaming pipeline has a 
critical bug in handling tools with empty input schemas. The code ignores the 
initial input value from the API and then tries to parse an empty string, 
resulting in a JSON parsing error instead of tool execution.

ROOT CAUSE
================================================================================
File: src/ai/streaming.rs
Issue: Two streaming code paths with identical bugs

When ContentBlockStart arrives with ToolUse { id, name, input }, the code:
1. Uses pattern ".." to ignore the input field
2. Clears tool_input_buffer to empty string ""
3. Does NOT initialize buffer with the input value from API

When ContentBlockStop arrives, the code:
1. Tries to parse the buffer as JSON
2. Buffer is empty ("") for tools with no input properties
3. serde_json::from_str("") fails with "EOF while parsing"
4. Sends Error event instead of ToolUseComplete
5. Tool handler never executes

HOW IT AFFECTS EnterPlanMode
================================================================================
1. EnterPlanMode schema has "properties": {} (no input properties)
2. Anthropic API sends: content_block_start with input: {}
3. API does NOT send input_json_delta (input already complete)
4. Code clears buffer, ignoring initial input: {}
5. At content_block_stop, buffer is empty ""
6. Parsing "" fails
7. User sees error: "Failed to parse tool input: EOF while parsing"
8. Tool never executes, plan mode never activates

WHY THIS BUG EXISTS
================================================================================
1. Pattern matching with ".." silently ignores the input field
2. The initial input: {} is never used
3. Buffer is cleared unconditionally
4. No fallback for empty input case
5. Only tools with input properties work (they get input_json_delta events)
6. Tools with empty input schemas immediately fail

THE FIX
================================================================================
Two streaming code paths need identical changes:

1. Capture the input field (don't ignore with ..)
2. Initialize buffer with serialized input value
3. Accumulate InputJsonDelta chunks on top of initial input
4. Handle empty buffers at ContentBlockStop

Example fix for StreamingHandler::process_stream:

    ContentBlock::ToolUse { id, name, input } => {  // ← Capture
        current_tool_id = Some(id.clone());
        // Initialize with initial input
        tool_input_buffer = serde_json::to_string(&input)
            .unwrap_or_else(|_| "{}".to_string());
        let _ = tx.send(StreamingUpdate::ToolUseStart { id, name });
    }

    // At ContentBlockStop:
    if let Some(id) = current_tool_id.take() {
        if tool_input_buffer.is_empty() {
            tool_input_buffer = "{}".to_string();
        }
        match serde_json::from_str(&tool_input_buffer) {
            Ok(input) => {
                let _ = tx.send(StreamingUpdate::ToolUseComplete { id, input });
            }
            Err(e) => {
                let _ = tx.send(StreamingUpdate::Error(
                    format!("Failed to parse tool input: {}", e)
                ));
            }
        }
    }

Apply same pattern to StreamProcessor::process (lines 393-452)
